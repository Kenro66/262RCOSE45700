# EC2 数据库迁移

CD 等待现有 PostgreSQL 容器就绪并停止后端后，按文件名顺序执行
`storage/migrations/` 中尚未登记的迁移，再重启后端。
`public.schema_migrations` 保存已成功执行的文件名和时间。
每批待执行的 SQL 和登记记录共用一个事务。SQL 出错时事务回滚，发布停止。

首次启用前备份现有数据库。本仓库的 `045`、`070` 和 `071`
可在已应用过对应 SQL 的数据库上重复执行，因此初次部署会补跑并登记这三个文件。
新建数据库仍由 `storage/schema.sql` 初始化，再运行相同迁移流程。

新增迁移使用递增的三位数字前缀，例如 `072_add_column.sql`。
已部署的文件应保留原名和内容，后续调整放入新文件。
部署在后端停止期间运行迁移，以防旧进程在清理后写回旧数据。
迁移文件由脚本统一管理事务，请只写能在 PostgreSQL 事务内执行的 SQL，
并省略 `BEGIN`、`COMMIT`、`ROLLBACK` 和 psql 元命令。
后续部署步骤失败时，已提交的迁移仍保留。
EC2 部署会先快进代码检出再迁移。迁移失败时，脚本会停止发布并尝试启动后端。

需要在独立环境手动执行单个迁移文件时，可以使用 `psql -X -v ON_ERROR_STOP=1 --single-transaction -f 文件名`。
